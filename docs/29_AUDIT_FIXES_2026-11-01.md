# 29 — Comprehensive Audit Fixes (1 November 2026)

This document records the fixes applied following the 1 November 2026 Comprehensive Audit (`NF01`–`NF24` and open items from `F01`–`F21`).

## 1. Automated Recurring Engine (`NF01`, `NF02`, `NF20`)
* **Single-Transaction Atomicity (`app/worker/index.ts`)**: `runRecurringBatch` now executes the `INSERT INTO documents`, `UPDATE number_sequences`, `INSERT INTO document_lines`, `UPDATE recurring_templates`, and `INSERT INTO audit_events` inside a single atomic `env.DB.batch(...)` guarded by a per-invoice `create_token`. A mid-flight error can never wedge `number_sequences` or leave an issued invoice without lines.
* **Schedule & Frequency Guards (`app/worker/index.ts`)**: `previewRecurringRun` and `runRecurringBatch` now enforce `t.start_date <= ?` and support both `monthly` and `annually` templates (evaluating `annually` templates only in their anniversary month).
* **Multi-Company Cron (`app/worker/index.ts`)**: `scheduled()` iterates over all companies where `set_up = 1` and respects `CRON_ENABLED !== "0"`.
* **Reactive Store Refresh (`app/src/pages/Recurring.tsx`)**: `RecurringPage` re-fetches preview on company change/reload and calls `useApp().reload()` after batch execution.

## 2. Outbound Email Delivery & Banking Redaction (`NF03`, `NF05`, `NF06`)
* **Honest Delivery Status (`app/worker/index.ts`)**: `sendDocument` and `sendCustomerStatement` no longer silently record `status = 'sent'` when `RESEND_API_KEY` is missing in production (returning HTTP 503 with a clear setup message) or when Resend returns an error (recording `status = 'failed'`, leaving `documents.sent_at` unset, and returning HTTP 502).
* **Itemized Email Body (`app/worker/index.ts`, `app/src/pages/Documents.tsx`)**: Replaced the misleading *"Please find attached"* text with an itemized line-item summary, due date, total, and dynamic banking details.
* **Dynamic Banking Details & Deduplication (`app/src/data.ts`, `app/src/pages/Paper.tsx`, `app/src/pages/Statement.tsx`)**: Banking details are parsed dynamically from the company's `default_message` / snapshot (`parseBankDetails`), removing hardcoded bank account numbers from the public GitHub repository (`NF06`, `F19`) and stripping duplicate 7-line banking blocks from `p.message` (`stripRedundantBankLines`, `NF05`).

## 3. FNB Bank Reconciliation (`NF07`, `NF08`, `NF09`, `NF10`, `NF24`)
* **Restore Ignored Transactions (`app/worker/index.ts`, `app/src/pages/Banking.tsx`)**: `POST /api/bank/unmatch` now restores `"ignored"` transactions back to `"unmatched"`, fixing the broken **Restore** button on the Ignored tab.
* **Atomic Match & Unmatch (`app/worker/index.ts`, `app/src/pages/Banking.tsx`)**: `handleBankMatch` and `handleBankUnmatch` execute payment creation/voiding, transaction status updates, and audit logging in a single atomic `env.DB.batch(...)`, and `Banking.tsx` triggers `useApp().reload()` so global invoice statuses update immediately.
* **RFC 4180 CSV Parsing & Batched Import (`app/worker/index.ts`)**: `parseCsvRows` handles multi-line quoted CSV fields before splitting rows, `hashBankTx` tracks same-day duplicate row occurrences within a statement, and `handleBankImport` batches inserts in chunks of 25 statements to stay well below Cloudflare D1 query limits.
* **FIFO & Word-Boundary Matching (`app/worker/index.ts`)**: `suggestMatchForTx` prioritizes Plutus `source = 'app'` invoices, matches oldest unpaid invoices first (FIFO), and uses word-boundary regular expressions for customer name matching.

## 4. Customer Statements, UI & Security (`NF04`, `NF11`–`NF19`, `NF21`–`NF23`)
* **Aging Bucket Credit-Note Reconciliation (`app/worker/index.ts`)**: `getCustomerStatement` applies credit notes against the oldest aging buckets first (`days90` → `days60` → `days30` → `current`) so the 4 aging buckets always sum to `Total Due`.
* **Pre-Cutover Sage Filter (`app/worker/index.ts`, `app/src/pages/Statement.tsx`)**: Added `onlyApp=1` filter and a one-click UI toggle on `Statement.tsx` so unverified pre-Plutus Sage invoices (post-Feb 2022) can be excluded before printing or emailing a customer statement.
* **Customer & Item Guards (`app/worker/index.ts`, `app/src/pages/Customers.tsx`, `app/src/pages/Editor.tsx`, `app/src/pages/Other.tsx`)**:
  * Enforced `company_id` checks on `PUT /api/customers/:id` and `PUT /api/items/:id`.
  * Separated annual recurring templates from the **Monthly recurring** column in `CustomerList`.
  * Changed `+ New invoice` on `CustomerView` to open a fresh invoice pre-selected for that customer (`?customer=:id`) alongside a dedicated **Copy last** button.
  * Added missing `.modal-backdrop`, `.modal`, `.field-lbl`, `.p-bank-lbl`, and mobile error visibility rules in `app/src/styles.css`.
  * Updated `app/tests/worker-regression.mjs` to use cross-platform `os.tmpdir()` and `python3`/`python` fallback.
